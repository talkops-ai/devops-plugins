# Amplify Sandbox, Production Hosting, CI/CD, and Monorepo Architecture

Use this skill whenever provisioning personal cloud sandboxes, authoring `amplify.yml` build specifications, configuring branch-based production/staging environments on AWS Amplify Hosting, setting up monorepo/multi-repo topologies, or planning an Amplify Gen 1 to Gen 2 migration.

## Six Non-Negotiable Deployment Guardrails

1. **Always Pass `--once` to `npx ampx sandbox` in Non-Interactive Agent Sessions:**
   - Running `npx ampx sandbox` without `--once` starts an infinite file-watcher loop that hangs agent execution. Always run `npx ampx sandbox --once` (and `--outputs-format dart --outputs-out-dir lib` for Flutter).
2. **Never Fabricate or Commit `amplify_outputs.json`:**
   - `amplify_outputs.json` is generated by `npx ampx sandbox --once`, `npx ampx pipeline-deploy`, or `npx ampx generate outputs` and **MUST** remain in `.gitignore` along with `.amplify/` and `.env*`.
3. **Match `artifacts.baseDirectory` to the Exact Frontend Framework:**
   - Setting the wrong `baseDirectory` in `amplify.yml` causes a silent blank page in production:
     - React / Vue (Vite): `dist`
     - Next.js (SSR / App Router): `.next`
     - Next.js (Static Export `output: 'export'`): `out`
     - Angular: `dist/<project-name>/browser`
     - Create React App: `build`
4. **Provision the `AmplifyBackendDeployFullAccess` IAM Service Role Before Branch Deployment:**
   - `npx ampx pipeline-deploy` inside Amplify Hosting fails with `AccessDeniedException` unless the Amplify App has an IAM Service Role (`amplify.amazonaws.com` trust policy) attached via `aws amplify update-app --app-id $APP_ID --iam-service-role-arn $ROLE_ARN`.
5. **Monorepo `appRoot` Rules:**
   - `appRoot` in `amplify.yml` **MUST NOT** start with a leading slash (`appRoot: packages/web`, never `/packages/web`).
   - In a monorepo with multiple frontends sharing one Amplify backend, only **one** app runs `npx ampx pipeline-deploy`; sibling frontend apps run `npx ampx generate outputs --branch $AWS_BRANCH --app-id <BACKEND_APP_ID>`.
6. **Sandbox Secrets Do Not Copy to Hosting Branches:**
   - `npx ampx sandbox secret set KEY` scopes secrets only to the developer's personal sandbox. Production/staging branches require `npx ampx secret set KEY --branch <branch> --app-id <app-id>`.
